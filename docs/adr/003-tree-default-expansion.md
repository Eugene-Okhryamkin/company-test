# ADR-003: Раскрытие дерева по умолчанию и хранение состояния раскрытия

- **Статус:** принято
- **Дата:** 2026-09-15
- **Этап:** 01 FOUNDATION

## Контекст

Требование: «Интерактивное дерево: раскрытие/скрытие ветвей, второй уровень открыт по умолчанию».

Формулировку можно понять двумя способами:

1. **Второй уровень виден:** дивизионы (уровень 1) раскрыты, отделы (уровень 2) показаны, команды (уровень 3) скрыты.
2. **Второй уровень раскрыт:** раскрыты и дивизионы, и отделы, видны все три уровня.

При трёх уровнях в данных вариант 2 сразу показывает всё дерево, и раскрытие теряет смысл при первом открытии.

Кроме того, данные будут обновляться (SWR на этапе 01, live-патчи на этапе 03). Если состояние раскрытия вычислять заново при каждом обновлении, раскрытые пользователем ветки будут сворачиваться.

## Решение

- Выбран **вариант 1**: `DEFAULT_EXPANDED_DEPTH = 1`. Узлы уровня ≤ 1 раскрыты, поэтому второй уровень виден сразу.
- Состояние раскрытия хранится как **пользовательские переключения** (`Map<id, boolean>`) поверх значения по умолчанию, которое зависит от уровня: `isExpanded = overrides.get(id) ?? level <= DEFAULT_EXPANDED_DEPTH`.
- Глубину можно передать параметром (`useTreeExpansion(depth)`), так что перейти на вариант 2 — это изменить одну константу.

## Альтернативы

| Вариант | Почему не выбран |
|---|---|
| Вариант 2 (depth = 2) | Всё дерево сразу раскрыто, интерактивность при первом открытии не нужна |
| Хранить полный `Set` раскрытых id, заполняемый при загрузке | Новые узлы из обновлений не получают значение по умолчанию; нужно синхронизировать `Set` с данными |
| Состояние в каждом `OrgTreeItem` (`useState`) | Теряется при перемонтировании ветки и недоступно снаружи (понадобится на этапе 02 для «клик по строке таблицы выделяет узел в дереве») |

## Последствия

- ➕ Раскрытие переживает обновления данных; новые узлы получают разумное значение по умолчанию.
- ➕ Состояние сосредоточено в одном хуке, его легко поднять выше для синхронизации с таблицей (этап 02).
- ➖ При смене `toggle` перерисовываются все `OrgTreeItem`, так как меняется функция `isExpanded`. Для десятков узлов это незаметно; при росте дерева можно передавать в строки готовый флаг `expanded`.
