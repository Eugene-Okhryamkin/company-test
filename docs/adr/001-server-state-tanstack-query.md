# ADR-001: Серверное состояние и кэш запросов через TanStack Query

- **Статус:** принято (заменяет первоначальный вариант с собственным кэшем)
- **Дата:** 2026-09-15
- **Этап:** 01 FOUNDATION

## Контекст

Требования задания к работе с API:

- запросы идут через слой кэширования со stale time 5 секунд;
- лишние запросы не отправляются (stale-while-revalidate или аналог);
- кэш сбрасывается только при реальном изменении данных;
- при размонтировании компонента запрос корректно отменяется;
- обрабатываются состояния загрузки, ошибки и пустого ответа.

На этапе 03 появятся live-патчи: клиент должен будет точечно менять данные в кэше, не перезапрашивая их целиком.

Сначала был написан собственный `QueryClient` на `useSyncExternalStore` (~150 строк плюс тесты). Он выполнял требования, но дублировал зрелую библиотеку, которую пришлось бы поддерживать самим.

## Решение

Использовать **TanStack Query 5**. Настройки проекта собраны в `client/src/shared/api/query-client.ts`:

```ts
queries: {
  staleTime: 5_000,            // данные свежие 5 с
  retry: false,                // ошибка сразу видна, повтор — кнопкой «Повторить»
  refetchOnWindowFocus: true,  // перепроверка при фокусе, только для устаревших данных
  structuralSharing: true,     // равные данные сохраняют ссылку
}
```

Запрос описан через `queryOptions` в `entities/org-node/api/org-tree.query.ts`, а `signal` из TanStack передаётся в `fetch`:

```ts
queryFn: ({ signal }) => fetchOrgTree(signal)
```

| Требование | Механизм TanStack Query |
|---|---|
| Stale time 5 с | `staleTime` |
| SWR, без лишних запросов | кэш по `queryKey`, фоновая перепроверка, дедупликация |
| Отмена при размонтировании | отмена через переданный `signal`, когда у запроса нет наблюдателей |
| Изменение только при реальных изменениях | structural sharing + перерисовка только при изменении используемых полей результата |
| Точечные патчи (этап 03) | `queryClient.setQueryData(orgTreeQueryKey, updater)` |

Каждое требование закреплено тестом в `org-tree.query.test.tsx`. Тесты проверяют поведение, а не устройство библиотеки: при выключенном `structuralSharing` падают 4 теста.

## Альтернативы

| Вариант | Почему не выбран |
|---|---|
| **Собственный кэш** (первая реализация) | Повторяет возможности TanStack Query, но без devtools, сборки мусора, повторов и проверки временем; его пришлось бы поддерживать самим. Экономия ~9 КБ gzip при лимите 200 КБ несущественна |
| **SWR (Vercel)** | Нет автоматической отмены через `AbortSignal` при размонтировании; stale time приходится эмулировать через `dedupingInterval` |
| **`useEffect` + `useState`** | Нет общего кэша, дедупликации и SWR; повторное монтирование всегда отправляет запрос |

## Последствия

- ➕ Стандартное, хорошо документированное решение; меньше собственного кода и тестов на инфраструктуру.
- ➕ Есть `setQueryData` для live-патчей этапа 03 и `ReactQueryDevtools` (при необходимости, только в dev).
- ➕ Structural sharing сохраняет ссылки на неизменённые узлы, поэтому мемоизированные строки дерева не перерисовываются.
- ➖ +~9 КБ gzip к бандлу (116.8 КБ сейчас, лимит 200 КБ).
- ➖ Поведение зависит от настроек по умолчанию библиотеки, поэтому ключевые настройки заданы явно и проверены тестами.
